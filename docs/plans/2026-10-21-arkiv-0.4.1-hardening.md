# arkiv 0.4.1 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the security and data-loss findings of the 2026-10-21 review in a 0.4.1 patch release, each with the regression test it lacks today.

**Architecture:** Fixes stay inside the existing modules. Two small consolidations carry fixes with them: one shared source-file walk in `bundle.py` (fixes the `media/` symlink hole), and one "build a database from a directory" path in `database.py` that builds into a fresh temp file and atomically replaces the output (fixes stale collections and lost writes, and removes three duplicated import blocks in `cli.py`). No format change.

**Tech Stack:** Python 3.8+, stdlib `sqlite3` / `zipfile` / `tarfile` / `gzip`, PyYAML, pytest, coverage 7.10+.

**Spec:** `docs/reviews/2026-10-21-full-review.md` (finding IDs below refer to it; decisions in its "Decided 2026-10-21" section).

## Global Constraints

- Runtime floor stays Python 3.8: no `Path.is_relative_to`, `str.removeprefix`, `match`, or runtime `X | Y` types.
- No new runtime dependencies (`pyyaml` only); `bundle.py` stays stdlib-only.
- Any error that should reach a CLI user is a `ValueError` or `FileNotFoundError` (`cli.main` prints those as `Error: ...` with exit 1; anything else is a traceback).
- `arkiv_format` stays `"0.2"`: this release changes no on-disk structure.
- Bundles stay byte-reproducible (same members, same bytes).
- New and changed code is black-clean at line length 88; do not reformat untouched code (a repo-wide black pass is separate work, review item Q14).
- No em-dashes in any `.md` file (a commit hook rejects them).
- Version string `0.4.1` in both `pyproject.toml` and `src/arkiv/__init__.py`.

## Review Focus

1. A legitimate archive with a symlink pointing inside itself (`media/latest.jpg -> 2024.jpg`): conversion succeeds, the real file comes through, the link is skipped. Test in Task 2.
2. A database created by 0.4.0 or earlier (no `_schema.example` column) opened by 0.4.1, read-only and writable: no crash, writable open migrates. Test in Task 9.
3. An archive whose `schema.yaml` was exported by 0.3/0.4 and already carries a bogus `values: [id-0]` on a high-cardinality key: the next convert and export heals it. Test in Task 9.
4. Database paths containing spaces, `%`, or non-ASCII characters in read-only mode: they open the right file and create nothing else. Test in Task 4.
5. A rebuild that fails partway (for example a collection collision): the previous `arkiv.db` is untouched and no temp file is left in the archive directory. Test in Task 7.

### Task 7: Rebuild databases from scratch, never over unexported writes (L1, L2, C1, Q2)

**Files:**
- Modify: `src/arkiv/database.py` (new `Database.import_directory`, `build_database`, `refuse_unexported_writes`)

- Modify: `SPEC.md` 3.2 Notes (the "use `arkiv convert` to refresh the schema" advice)
- Test: `tests/test_cli.py`, `tests/test_status.py`

**Interfaces:**
- Produces: `Database.import_directory(self, source_dir: PathLike) -> int`: `import_readme` when `README.md` exists; otherwise every root-level `*.jsonl` yielded by `iter_source_files` (sorted, no `/` in `rel`) through `import_jsonl`, then `import_assets`. Raises `ValueError(f"Directory has no README.md and no .jsonl files: {source_dir}")` when there is neither.
- Produces: `refuse_unexported_writes(db_path: PathLike) -> None`: if `db_path` exists and `get_unexported_writes() > 0` (opened read-only), raises a `ValueError` whose text contains `unexported write` and the command `arkiv convert {db_path} <directory>`.
- Produces: `build_database(source: PathLike, output: PathLike, *, fingerprint: bool) -> int`: `source` is a directory or a `README.md` file. Calls `refuse_unexported_writes(output)`, builds into `tempfile.mkstemp(dir=output.parent, prefix=".arkiv-", suffix=".db")` (dot prefix keeps it out of every source walk), populates it (`import_directory` or `import_readme`), calls `store_source_fingerprint(<directory>)` when `fingerprint`, closes, then `os.replace(tmp, output)`. On any exception the temp file is removed and the exception re-raised. Returns the record count.
- Consumes: `iter_source_files` (Task 2).

CLI wiring:
- bundle input: `build_database(tmpdir, output, fingerprint=False)`
- directory input: `build_database(input_path, output, fingerprint=True)`
- `.md` input: `build_database(input_path, output, fingerprint=False)`
- `.jsonl` input: `refuse_unexported_writes(output)`, then `import_jsonl` as today (a single JSONL still replaces only its own collection)
- `_resolve_db` directory branch: rebuild through `build_database(path, db_path, fingerprint=True)` when the db is missing or stale; the guard now lives in `build_database`
- db to directory: after a successful export to a directory (not a bundle) with neither `--since` nor `--until`, open the database writable and call `store_source_fingerprint(output)`. That resets `inserts_since_convert` (C1): the writes now exist in a directory form, so a later rebuild loses nothing.

```python
class _CappedTarInfo(tarfile.TarInfo):
    def _proc_gnulong(self, tarfile):

        _check_header_size(self.size)
        return super()._proc_pax(tarfile)
```
